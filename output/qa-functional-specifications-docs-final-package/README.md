# Portfolio QA - Especificaciones funcionales y trazabilidad

Este repositorio presenta un caso práctico de QA funcional y análisis de requerimientos basado en escenarios profesionales anonimizados, generalizados y adaptados para portfolio.

> Nota de confidencialidad: este material no contiene información real ni confidencial de clientes. Los escenarios fueron modificados para proteger acuerdos de confidencialidad y se usan exclusivamente para demostrar metodología de trabajo QA.

## Objetivo

Demostrar mi capacidad para transformar necesidades de negocio en artefactos QA trazables: FSD, historias de usuario, reglas de negocio, precondiciones, criterios de aceptación, escenarios Gherkin, matriz de trazabilidad, evidencias de ejecución y bugs encontrados simulados.

## Rol representado

QA Analyst / Functional Analyst, con foco en:

- análisis funcional;
- validación de requisitos;
- diseño de casos de prueba;
- testing funcional y end-to-end;
- trazabilidad entre requisitos y pruebas;
- comunicación de bugs encontrados;
- validación de APIs y datos como línea de evolucion profesional.

## Artefactos incluidos

| Carpeta | Contenido | Propósito |
|---|---|---|
| `01-contexto-del-proyecto/` | Contexto funcional y FSD | Explicar alcance, supuestos, reglas, formatos y flujos base |
| `02-historias-de-usuario/` | HU con estructura Scrum | Definir necesidad, reglas, precondiciones y criterios en formato Dado/Cuando/Entonces |
| `03-casos-de-prueba/` | Escenarios Gherkin en inglés | Validar flujos y riesgos funcionales |
| `04-matriz-trazabilidad/` | Matriz Excel y guía de lectura | Conectar HU, criterios y casos |
| `05-evidencias/ejecucion-manual/` | Reportes de ejecución simulada | Mostrar criterio de validación |
| `05-evidencias/bugs-encontrados/` | Bugs encontrados simulados | Demostrar comunicación de hallazgos |
| `07-postman/` | Evidencia complementaria de pruebas API con Postman | Documentar escenarios, colección y datos de prueba incluidos |
| `08-playwright/` | Base documental para automatización | Describir el alcance inicial de futuras pruebas con Playwright |

## Como revisar el proyecto

1. Leer el contexto funcional y el FSD.
2. Revisar cada historia de usuario.
3. Consultar los casos de prueba en Gherkin.
4. Validar la cobertura en la matriz de trazabilidad.
5. Revisar evidencias de ejecución manual simulada.
6. Revisar los bugs encontrados para entender análisis de impacto, severidad y prioridad.
